# Flow: write_acceptance_criteria

## Goal
Produce testable, unambiguous Acceptance Criteria in Gherkin style.

## Rules
- Each AC must be observable and testable.
- Include: happy path, validation, error handling, and edge cases (as relevant).
- Include NFRs if relevant (perf, accessibility, security, observability).

## Output
A numbered list under `## Acceptance Criteria`.
